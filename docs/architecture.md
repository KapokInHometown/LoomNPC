# 行为如何进入世界

Loom NPC 将模型与世界修改隔开。行动模型只返回结构化意图，世界规则决定行动是否能发生；可选台词模型在成功执行后生成展示文本，不参与规则判定或状态变更。默认实现保持离线和确定性。

## 一次决策

```text
输入 → 观察 → 记忆检索 → 上下文 → 模型 / 固定行动
                                      ↓
                             解析 → 校验 → 执行或拒绝
                                      ↓
                                  事件与记忆
                                      ↓
                      可选：非秘密 speak → 生成台词或模板回退
                                      ↓
                                   完整 Trace
```

观察和上下文按行动角色构建，只包含该角色已知事实和当前位置可见的人物。模型适配器接收这份上下文，不接收完整世界对象。开发者界面可以展示完整世界，但这份调试数据不会成为模型上下文。

角色知道秘密，并不意味着有权向任何人透露。知识检查与披露权限分别校验：Mara 知道灯塔秘密，但交信前没有披露条件；Ivo 知道暗道，Mara 的上下文中没有暗道内容。

## 记忆检索

检索只读取当前角色的记忆，返回最多五条独立副本；调用方可指定数量。查询和摘要统一做 Unicode NFKC 与大小写归一化，标点、空白和中英文边界分隔词元。连续中文按相邻双字片段匹配，单字词元按单字匹配，英文与数字按完整词匹配。例如“你还记得那封失落的信吗”与信件摘要共享“失落”“落的”“的信”，不需要整句原样出现。

相关性是不同查询词元的命中数，重复词元不增加权重。先按相关性降序，再按 importance、tick、id 降序，排序不依赖记忆存储顺序。零匹配记忆仍可填充结果；空查询或无匹配查询按后三项排序。它是无外部依赖的字面检索，不识别同义改写，也不提供语义相关性保证。

## 模型接入

默认适配器是确定性 Mock。显式选择 DeepSeek 时，集中提示词将角色上下文与三种行动的 schema 组合为请求。供应商 HTTP 调用只发生在适配器中，核心与界面不接触密钥，也不依赖供应商 SDK。

DeepSeek 使用 JSON 输出和非思考模式，每次行动决策最多请求一次，可选台词阶段另请求一次，网络超时可配置。认证失败、余额不足、限流、网络错误、空输出和截断均返回固定的安全错误消息；不把供应商响应正文或认证请求头写入错误记录，不跟随 HTTP 重定向。行动模型响应还需经过原有 parser、verifier 和 executor，不能直接修改世界。

网页由本地服务选择模型；重置世界保留所选行动和台词适配器。固定行动按钮不请求行动模型，启用台词生成后合法非秘密说话仍可请求台词模型。网页评测始终在独立世界使用 Mock。启用在线模型后，玩家输入及对应阶段的角色上下文会发送到 DeepSeek。

## 离线决策

Mock 不识别任何世界专属角色、物品、地点或话题标识，只读取当前角色上下文。角色目标、信任和记忆仍供 adapter 使用；Mock 的有限指令解析依据本地可见标签，不读取全局任务状态或规则，也不尝试规划多步任务。

物品、地点和事实记录可选配 `aliases`，值是无重复、非空文本列表。例如事实 `forge_plan` 配置 `"aliases": ["开工计划", "开工说明", "说明"]`。未配置时仍可使用标识，物品、地点还可使用名称，事实还可使用完整模板文本。角色通过可见的名称或标识指定。标签只随持有物品、当前及相邻地点、已知事实进入上下文，未知事实、远处角色及未持有物品的标签不会额外暴露。

输入与标签按 Unicode NFKC 和大小写归一化，中文按字面包含匹配，英文与标识按完整词边界匹配。匹配中被更完整标签包含的短标签让位于完整标签；独立标签命中多个对象或相同别名对应多个对象时显式失败，结果不依赖字典顺序。

先识别“前往、走到、移动、进入、去、move、go to”，再识别交付动词或只含持有物品标签的输入，其余输入匹配已知话题。可使用“交矿石”“把矿石交给工匠”“give ore to smith”“请向学徒说明开工计划”“进入锻造间”。目标可放在“给、对、向、to”之后；“我、你”或未指明目标时仅在有唯一可见交谈者的情况下成立。多个可见角色必须指明名称或标识。问候也由已知话题别名声明，如“你好、hello”。

请求没有行动权限、物品不在背包、地点不相邻、话题未知或目标缺失/歧义时，Mock 抛出安全的 `ModelError`，Runtime 记录 `model_error`，世界不变。明确匹配的行动仍交给 verifier 检查信任、秘密和任务条件：工坊备料前说明计划返回 `SECRET_LOCKED`，未听取说明进入锻造间返回 `BRIEFING_REQUIRED`。远处 Ivo 的“你好”现在在决策阶段因没有可见目标失败；离线距离评测使用固定提案，继续检验 verifier 的 `OUT_OF_REACH` 边界。

## 行动边界

行动字段严格匹配各自 schema，不能夹带任意世界状态更新：

```jsonl
{"type":"speak","actor_id":"mara","target_id":"player","topic":"lighthouse_secret"}
{"type":"move","actor_id":"player","location_id":"tower"}
{"type":"give","actor_id":"player","target_id":"mara","item_id":"letter"}
```

说话使用话题标识，执行器从世界事实与角色模板生成规范台词。这个设计能检验已声明话题的知识和秘密权限；它不能推导出任意自然语言都不会泄密。可选生成台词的边界如下，与行动校验分别记录。

校验负责角色、对象、位置、物品所有权和任务前置条件。执行器负责物品转移、位置变化、事实传播、信任、任务状态及事件记忆。被拒绝的行动仍记录 trace，但不会推进世界 tick 或修改世界。

## 生成式台词

台词生成默认关闭，通过 `Runtime(..., speech_adapter=...)` 独立注入，CLI 通过 `run --provider deepseek --generate-speech` 开启。行动 Adapter 的 `generate_decision(context) -> ModelDecision` 与台词 Adapter 的 `generate_speech(context) -> ModelSpeech` 分开；现有行动适配器无需新增方法。DeepSeek 同时实现两个接口，分别使用 `loom-actions-v2` 与 `loom-speech-v1` 提示词。两次请求都是无会话历史的独立请求，台词请求不携带行动请求或其秘密上下文。

职责分为四层：行动模型选择 `speak/move/give`；parser 与 verifier 校验结构及规则；executor 确定性提交登记行动；台词层在执行成功后尝试生成一次自然语言回复。行动 schema 不新增 `text`，executor 不接收模型台词。自由文本既不能触发任务效果，也不能替换知识校验。

只有已执行的非秘密 `speak` 可以生成台词。秘密话题无论披露条件是否满足，都不调用台词 Adapter；合法秘密行动仍由原有 executor 披露固定模板。拒绝行动、决策或解析失败、执行失败与其他行动不产生台词记录。模型失败或输出不合格式时回退固定模板；台词失败不撤销已经成功提交的规范行动，也不把该行动标成模型失败。

台词上下文从行动前快照和角色上下文投影，包含人设、目标、输入、可见目标、观察、公开认知标识、过滤后的检索记忆和本次获准话题的格式化模板 `approved_fact`。公开认知标识仅保留角色已知、非秘密且当前可向接收者执行说话的事实；不附加其他事实正文。涉及秘密话题或当前不能向接收者说出的历史事件及其记忆会被排除，其余条目保持原检索顺序，不补入全局历史。即使双方曾听过某个秘密，该历史也不会进入台词请求。

这些过滤基于结构化来源，不是语义过滤器。世界作者须保证 persona、goal、名称标签、非秘密模板和规则摘要适合公开表达；玩家输入可能包含不可信文本。提示词要求遵守获准事实、保持角色风格并将输入视为游戏数据，但不能阻止所有注入、模型幻觉、秘密猜测、改写或隐性泄密。首版不提供秘密台词生成，也不声称公开话题下的自由文本已经安全。

输出严格为 `{"text": "角色回复"}`，不接受重复字段、额外行动、非文本、空白、超过 1000 字符或不适合展示的控制字符。此检查仅验证格式及展示长度；任何格式合法但编造事实的文本仍标记 `semantic_validation=not_performed`。需完整语义保证的调用方应继续使用默认模板模式。

世界的事实集合、接收者已知话题、任务状态、事件与记忆只由规范行动更新，记录中 `execution.speech` 是固定模板。展示文本位于独立的 `speech.text`，不会回写事件摘要、双方记忆或 belief，不会自动进入下一回合 context。规范事件描述的是登记行动的执行；生成文本与规范模板是否语义一致尚未验证。保留这一区别可避免未经验证的言语沿记忆管线变成后续行动的知识依据。

Trace 的可选 `speech` 字段记录：状态 `generated/fallback/skipped`、原因 `OK/MODEL_ERROR/INVALID_OUTPUT/SECRET_TOPIC`、实际台词上下文、原始输出、最终展示文本，以及未进行语义校验的标记。取得完整供应商响应后可附带该阶段独立的 `model_request`，不含认证头和密钥；故障只记录稳定代码，不保存异常正文。生成失败时 `raw_output` 为空；格式失败时保留原始文本供审查。字段缺失表示未启用或该行动不进入台词阶段。

回放先按原有规则重算行动与世界，再重建台词投影、核对输出解析及展示文本，或验证回退与秘密跳过的边界。它不重新生成台词，也不评估语义安全；模型故障只核对记录结构。旧的无 `speech` Trace 保持原有回放行为，启用与停用生成后可以在同一历史中混合记录。会话恢复使用启动时显式传入的台词 Adapter，不从存档读取配置或凭据。

离线回归由 `tests/test_speech.py` 的脚本化 Adapter 和模拟 DeepSeek 响应完成，覆盖上下文中的人设、观察与记忆、不同输入的输出记录、生成与格式失败、拒绝或其他行动不调用、秘密过滤和获准秘密的模板路径、生成文本不改变知识、两套世界共用管线、回放篡改拒绝、HTTP 和持久会话恢复。`examples.dialogue` 可输出完整演示并离线回放。测试证明数据流和回退边界，不衡量自然交流、人设一致性或语义泄密；现有 `eval`、`eval-live` 及 CI 的行动评测范围不变，真实台词质量仍需另行取样评估。

## 场景规则

信件交付、钥匙发放与灯塔通行定义在灯港镇世界 JSON 的 `rules` 中，校验器和执行器不识别这些场景标识。第二个世界 `examples/workshop.json` 使用另一组角色、地点、物品和任务，中文指令入口为 `python3 -m examples.workshop`，无需修改核心代码。

每条规则包含 `id`、`match`、`requires`、`reject`、`effects`、`summary_suffix`。`id` 在世界内唯一。`match` 必须指定现有行动类型，其余匹配字段是该行动 schema 的子集，所有字段按相等关系共同匹配。例如工坊通行规则：

```json
{
  "id": "start_forging",
  "match": {"type": "move", "actor_id": "apprentice", "location_id": "forge"},
  "requires": [{"type": "quest_state", "quest_id": "briefed", "value": true}],
  "reject": {"code": "BRIEFING_REQUIRED", "message": "需要先听取工匠的开工说明。"},
  "effects": [{"type": "set_quest", "quest_id": "started", "value": true}],
  "summary_suffix": "锻造任务开始。"
}
```

条件列表中的所有条件都必须满足；空列表表示无附加条件。条件仅支持：

| 条件类型 | 字段与含义 |
| --- | --- |
| `quest_state` | `quest_id`、布尔 `value`：任务标志等于指定值 |
| `has_item` | `actor_id`、`item_id`：指定角色持有物品 |
| `trust_at_least` | `actor_id`、`target_id`、非负整数 `minimum`：前者对后者的信任达到阈值，缺失分数按 0 处理 |
| `target_is` | `actor_id`：行动接收者是指定角色，仅用于 `speak/give` |

效果仅支持 `set_quest`（`quest_id`、布尔 `value`）与 `add_trust`（`actor_id`、`target_id`、正整数 `amount`）。每个效果可选配 `when` 条件列表，未满足时跳过该效果。灯港镇用“交信前任务标志为 false”限制信任奖励只增加一次；工坊先设置备料标志再增加信任，两个效果的条件仍读取同一份行动前状态。

执行顺序固定：先检查通用权限、知识、距离、所有权及事实披露条件，再按配置顺序检查所有匹配规则，返回第一条未满足规则的 `reject`。场景规则不能放宽通用校验。执行器再次校验，在副本上完成基础行动，再按规则和效果的列表顺序应用效果；匹配与 `when` 都读取行动前快照，不产生隐式连锁触发。多条规则修改同一标志时，后写入的值生效；信任增量累加。

`summary_suffix` 是追加到行动事件摘要的固定文字，与效果条件独立；它会进入该事件见证者的记忆，启用台词生成后可能随过滤后的记忆进入台词上下文。规则应避免在摘要中写入见证者不该知道的信息。规则不会直接暴露给模型上下文，也不能变更角色认知、物品、位置或任意 JSON 路径；这些变化仍由基础行动负责。所有修改、事件和记忆通过同一次校验后的提交生效，任一执行失败都不会修改真实世界。

加载世界时校验规则字段、类型和角色、地点、物品、事实、任务引用，不接受未知条件、效果或脚本。世界省略 `rules` 或使用空列表时，仅运行通用规则，不自动附加灯港镇行为。

## 网页展示

网页读取 `/api/state` 的世界快照与独立 `scenario.presentation`。角色选择、地点、任务标志、物品、信任、记忆和行动权限都来自当前世界；展示数据不进入 NPC context，不参与规则或会话回放。没有任务、信任关系、物品或话题时显示对应空状态，不依赖 `player` 或固定剧情标识。

`integrations/demo.py` 根据初始世界生成展示配置。只有世界标识、地点、物品、事实、规则、角色的身份与行动权限及角色与任务标识集合匹配随包灯港镇时，才加载 `data/lantern_town_demo.json` 的专属插画坐标、角色美术、剧情标签、进度文案、观察角色和快捷操作；相同世界名或标识不能单独启用该配置。其他世界使用通用地点视图，列出地点描述、有向连接与驻留角色，不需要额外展示文件。

通用文字建议来自所选角色的行动权限、持有物品、已知话题、同地角色与相邻地点。点击后只发送 `actor_id` 与普通文本，使用当前 adapter 决策；建议不判断信任或任务条件，不保证执行成功。事实别名优先作为话题名称，没有别名时显示话题标识。任务列表直接展示全部布尔标志，名称可取设置该标志的规则摘要或话题标签，未找到则使用任务标识；不会通过推断规则编排剧情。

灯港镇固定剧情按钮的请求正文集中在展示配置中，页面不直接引用其角色或任务字段。固定行动仍由 Runtime 校验；问候、秘密与钥匙请求仍走 adapter。当前角色可通过下拉框或地点中的角色按钮选择，普通输入在所有世界保留。JSONL 文件名由当前世界标识和回合数生成；回放结果列出全部角色位置。网页的 Mock 评测仍运行随包灯港镇评测，与当前世界独立，弹窗明确说明其场景范围。

## Trace 与回放

每次决策保存输入、实际上下文、模型原始输出、解析行动、校验与执行结果、错误、前后世界及状态差异。JSONL 一行对应一次决策。完整快照让首版更容易审查和复现，代价是长会话的文件体积会增长。

DeepSeek 取得完整有效响应后，会附带 `model_request`：供应商、实际提示词版本及不含认证信息的请求 payload（模型名、messages 和生成参数）。HTTP 失败或响应不完整时仅保留角色上下文与安全错误，不保存该字段。DeepSeek 的提示词版本以 `model_request.prompt_version` 为准；context 内版本字段标记上下文构造约定；Mock 的文本策略不参与回放重算。

回放不请求模型；它重新校验和执行记录中的行动，并检查记录与重算状态是否一致。上下文使用当前规则重建，因此检索规则变更若改变旧 trace 的记忆顺序或入选条目，该 trace 会因上下文不一致而校验失败。可选别名只读取记录中的世界快照；没有别名的旧快照仍生成原有上下文，Mock 策略更新不会重新调用模型或重新解释旧输入。解析失败会重新解析核对；模型故障和执行环境故障只核对失败结构与世界未变化，不重现外部故障。附带的 `model_request` 用于审查请求，不参与行动重算，也不认证模型输出来源。回放的初始世界来自记录，不能证明它曾来自某个可信服务器。

场景规则随 `before/after` 世界快照保存。启用生成台词时顶层增加可选 `speech` 字段，其余必填字段保持原有语义。回放使用记录中的规则，不读取当前示例文件；规则与实际效果不一致会导致重算失败。旧版灯港镇任务 trace 未保存规则，不能重现已移出的专属效果，应使用当前配置重新生成；运行时不通过场景名称补入隐式规则。

trace 属于开发者数据，包含全局调试状态和原始输入。不要把真实凭据或个人信息作为 Demo 输入，也不要把完整 trace 当作 NPC 的可见记忆。

## 本地会话

本地保存由 `--session-file` 显式开启，核心 Runtime 仍只持有内存世界和 trace。`Runtime.from_jsonl()` 使用现有回放重算完整历史，成功后构造独立的世界并保留原有 trace；可传入初始世界，要求第一条记录的 `before` 与配置完全一致。恢复出的 trace 数量决定下一次 trace 编号，世界 tick 和事件、记忆编号由重算世界延续；拒绝或失败的 trace 不推进 tick。

`SessionStore` 保存一行头记录（`format=loom-npc-session`、`version=1`、初始世界、trace 数量），后接原有 trace JSONL。头记录支持零行动会话，并检测尾部完整行丢失。加载先核对格式、版本、初始世界和数量，再走 Runtime 的回放恢复入口；不会采用回放失败时返回的部分世界，也不会静默创建新会话。存档不读取 adapter 或凭据。

保存前回放核对当前世界与全部 trace 一致；同目录临时文件写入并 `fsync` 后原子替换目标，文件权限由标准库临时文件保持为仅当前用户可读写。目标文件是唯一恢复入口，写入失败留下的临时文件供排查使用。每次保存重算完整历史，面向小型本地会话；不提供增量日志、压缩或跨进程协调，也不保证突然断电时目录元数据的持久性。

DemoSession 在同一把锁内串行处理决策、重置、保存和恢复。启用存储时，决策先在独立 Runtime 中执行，写入成功后替换当前 Runtime；恢复同样先在独立候选中完成全部校验和保存。保存或恢复失败保留当前会话与旧存档。外部模型请求已经发出时无法撤销，但其结果不会在保存失败后提交到会话。

`/api/restore` 显式接受普通 trace JSONL，核对当前配置的初始世界后替换会话；启用存储时同时保存。`/api/save` 只能写入启动时指定的路径，请求不能选择服务器文件。`/api/replay` 保持只读，导出的 trace 格式不变。重置会保存空的初始会话，重启不会重新载入重置前的历史。使用方式见 [本地会话保存与恢复](../README.md#本地会话保存与恢复可选)。

## 固定评测

评测读取随包提供的 JSON 场景，各场景从独立初始世界运行，返回逐项结构化结果。规则拒绝是某些场景的预期成功结果；“行动执行成功”与“评测通过”是两件事。

默认测试使用 mock adapter、模拟 HTTP 响应或固定行动，覆盖解析失败、知识隔离、秘密权限、合法执行、记忆、任务顺序、回放、供应商错误处理、凭据隔离与本地 HTTP 完整链路。默认 `eval` 与网页评测保持这个确定性路径。

## 真实模型评测

`eval-live` 显式选择供应商并创建独立的结果目录。评测层接收必传的 adapter 和安全模型元数据；供应商构建与凭据读取留在 CLI，核心运行循环不变。在线场景使用独立的 `live_evals.json`，仅允许角色与输入，不允许固定 action 或固定台词断言。整个配置在首次调用前完成校验，每个场景、每次重复都新建初始世界，所有输入走完整决策链路。

评测统计每次调用的输出、解析、规则校验和执行结果，并通过最终世界状态判断任务目标。规则拒绝可以满足保护边界的场景目标，但不等于任务完成；模型、解析或执行错误会使该轮未完成。后续固定步骤仍继续执行，不重试，也不切换 Mock。解析成功率以收到 action 原始输出的次数为分母，同时报告以全部调用次数为分母的有效 action 比例。任务完成率只统计标为 `task` 的场景，避免把边界保护结果混入任务成功率。

每轮 JSONL 保留原有 trace schema，可直接用 `replay` 离线校验。结果记录运行标识、UTC 起止时间、完整场景输入与目标、配置、逐步指标及文件/行号/trace id 引用。完整模型响应已有请求记录时，逐步 provider、model 和 prompt version 取自该记录；模型故障时使用显式运行配置，并标记来源，避免把 context 中的 Mock 版本误认成供应商提示词版本。评测结果不保存认证请求头、密钥或供应商错误正文。

在线调用不属于默认测试或 CI。评测链路用脚本化 adapter 和模拟供应商响应验证，真实模型分数需要另行显式运行取得。首版覆盖结构化行为和任务状态，尚未衡量真实模型的人设一致性、自由台词或长期角色表现。指标和场景格式见 [真实模型评测](live-evals.md)。

## 扩展入口

外部模型通过 `generate_decision(context)` 接入，并返回结构化决策；API key 应由外部配置注入，不能进入 context 或 trace。核心不引入供应商 SDK。

新增行动时，应一起更新 schema、校验器、执行器、固定场景、回放相关检查及测试。新增游戏引擎接入应放在 `integrations/`，避免让核心依赖引擎或界面。

新增世界时，通过世界 JSON 声明有限的场景条件与效果；无需修改校验器或执行器。当前配置面向布尔任务标志和信任增量，尚未提供脚本、完整任务编排或插件接口。默认 Mock 通过上下文中的实体标签和已知话题跨世界解析有限文本指令；世界可声明 `aliases`，无需改动 adapter。本地网页从当前世界配置展示角色、地点关系和任务状态，自定义世界可直接通过网页验证。

本地 HTTP 服务只监听 loopback，并串行处理同一个世界的决策。离线、在线评测和只读回放都不会修改当前 Demo 会话。当前结构提供显式启用的本地文件会话，面向单进程实验，尚未提供多会话或远程部署能力。
